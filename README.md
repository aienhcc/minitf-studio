# 🎪 미니TF 스튜디오

4인 미니 TF가 **근무 중 짬을 내 모여** 워크숍을 같이 굴리는 기획 보드.
HTML/CSS/JS 세 파일뿐이라 빌드 도구도, 서버도 필요 없습니다.

* **로그인** — kian / joon / eugene / sean 4개 계정, 첫 로그인 시 비밀번호 변경 강제
* **아이디어 보드** — 카드 + 👍/🤔 투표 + 코멘트
* **조 편성** — 테마조 정원 관리, 익명 닉네임 참가자, 본사/파견 섞는 자동 배정
* **타임테이블** — 반나절 블록을 드래그로 배치, 시각 자동 계산
* **예산 · 준비물** — 조별 활동비 자동 산출, 상한 대비 미터, TF 4명 담당 체크리스트
* **AI 스튜디오** — Gemini로 ① 아이디어 확장 ② 아이스브레이킹 콘텐츠 ③ 회의 정리 ④ 조 편성 추천
* **산출물 내보내기** — 지금 보드 내용을 기획서 한 장(MD / 인쇄용 HTML)으로 저장
* **모바일 우선** — 입력은 휴대폰으로, 확인·출력은 PC로 하는 걸 전제로 만들었습니다

## 지금 당장 확인만 하고 싶다면

`index.html`을 더블클릭해서 브라우저로 열면 **로컬 모드**로 바로 뜹니다.
닉네임만 넣고 들어가서 대시보드의 **“시작 템플릿 불러오기”** 를 누르면 화면이 어떻게 생겼는지 다 볼 수 있습니다.
이 상태는 로그인도 공유도 없고 내 브라우저에만 저장됩니다. 아래 설정을 끝내면 4명이 로그인해서 같이 씁니다.

준비할 게 딱 셋입니다. 총 25분쯤.

| 순서 | | 무엇 | 왜 | 누가 |

| **1번째** | **B** | GitHub Pages | 링크 하나로 접속 | **한 사람만** (관리자) |

B와 A는 대표 한 명(예: kian)이 하고, 나머지 3명은 링크 받아서 로그인만 하면 됩니다.
문서에서는 설명 편의상 A(Firebase)를 먼저 적어뒀으니, **작업은 B → A → C 순서로** 하시면 됩니다.

# A. Firebase 설정 (관리자 1명, 약 15분)

## A-1. 프로젝트 만들기

1. <https://console.firebase.google.com> 접속 → 구글 계정 로그인
2. **프로젝트 만들기** 클릭
3. 이름: `minitf` (아무거나) → 계속
4. **Google 애널리틱스: 사용 안 함** 으로 끄기 → **프로젝트 만들기**
5. 1분쯤 기다리면 완료 → **계속**

## A-2. Realtime Database 만들기

> ⚠️ **Firestore가 아니라 Realtime Database** 입니다. 둘 다 있어서 헷갈립니다.

1. 왼쪽 메뉴 **빌드(Build) → Realtime Database**
2. **데이터베이스 만들기**
3. 위치: **싱가포르 `asia-southeast1`** 선택 → 다음
4. 보안 규칙: **잠금 모드로 시작** 선택 → 사용 설정
   *(A-5에서 제대로 된 규칙을 넣을 거라 여기선 잠가둬도 됩니다)*
5. 화면 위에 뜨는 주소를 확인 — `https://minitf-xxxx-default-rtdb.asia-southeast1.firebasedatabase.app` 같은 형태

## A-3. 로그인 켜고 계정 4개 만들기

1. 왼쪽 메뉴 **빌드 → Authentication** → **시작하기**
2. **로그인 방법** 탭 → **이메일/비밀번호** 클릭 → 첫 번째 **사용 설정** 켜기 → 저장
   *(아래 "이메일 링크" 는 끄고 두세요)*
3. **Users(사용자)** 탭 → **사용자 추가** 를 4번 반복:

| 이메일 | 초기 비밀번호(예시 — 바꿔 쓰세요) |
|---|---|
| `kian@minitf.local` | `MiniTF-start-01` |
| `joon@minitf.local` | `MiniTF-start-02` |
| `eugene@minitf.local` | `MiniTF-start-03` |
| `sean@minitf.local` | `MiniTF-start-04` |

> **`@minitf.local` 이 뭔가요?** Firebase는 아이디를 이메일 형태로만 받습니다.
> 실제로 메일이 가는 주소가 아니라 그냥 형식을 맞추기 위한 가짜 도메인이고, 인증 메일도 보내지 않습니다.
> **사용자는 앱에서 `kian` 만 입력하면 됩니다** — 뒤에 `@minitf.local` 은 앱이 알아서 붙입니다.
>
> 초기 비밀번호는 6자 이상이면 되지만, **첫 로그인 때 8자 이상으로 바꾸도록 앱이 강제**합니다.

4. **가입 차단** (중요) — **설정(Settings) 탭 → 사용자 작업(User actions)** 에서
   **“생성(가입) 사용 설정”** 체크를 **해제** → 저장.
   이걸 꺼야 외부인이 임의로 계정을 만들어 들어오는 걸 막습니다.
   *(콘솔 버전에 따라 메뉴 이름이 조금 다를 수 있습니다. 못 찾겠으면 A-5의 강화 규칙을 쓰세요.)*

## A-4. 웹 앱 등록해서 config 받기

1. 왼쪽 위 **⚙️ → 프로젝트 설정**
2. 아래로 스크롤 → **내 앱** → **웹 아이콘 `</>`** 클릭
3. 앱 닉네임 `minitf-web` 입력 → (호스팅 체크는 **안 함**) → **앱 등록**
4. 화면에 이런 코드가 나옵니다. **중괄호 `{ ... }` 안쪽만** 통째로 복사하세요:

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "minitf-xxxx.firebaseapp.com",
  databaseURL: "https://minitf-xxxx-default-rtdb.asia-southeast1.firebasedatabase.app",
  projectId: "minitf-xxxx",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

> **`databaseURL` 줄이 없으면** A-2(Realtime Database 만들기)를 안 한 겁니다. 돌아가서 만들고 이 화면을 새로고침하세요.
> 이 값들은 **비밀이 아닙니다.** 공개돼도 되는 식별자이고, 실제 접근 통제는 다음 단계의 보안 규칙이 합니다.

## A-5. 보안 규칙 넣기

**Realtime Database → 규칙(Rules) 탭** → 내용 전체를 지우고 이 저장소의
[`database.rules.json`](database.rules.json) 내용을 붙여넣고 **게시**:

```json
{
  "rules": {
    "rooms":  { "$room": { ".read": "auth != null", ".write": "auth != null" } },
    "users":  { "$uid":  { ".read": "auth != null && auth.uid == $uid",
                           ".write": "auth != null && auth.uid == $uid" } }
  }
}
```

이제 **로그인한 사람만** 보드를 읽고 쓸 수 있습니다.

**(선택) 더 잠그고 싶다면** — A-3의 가입 차단을 못 찾았거나 확실히 4명만 막고 싶으면,
Authentication → Users 에서 각 계정의 **사용자 UID** 를 복사해 이렇게 바꾸세요:

```json
{
  "rules": {
    "rooms": { "$room": {
      ".read":  "auth != null && root.child('allow').child(auth.uid).val() == true",
      ".write": "auth != null && root.child('allow').child(auth.uid).val() == true"
    }},
    "users": { "$uid": { ".read": "auth.uid == $uid", ".write": "auth.uid == $uid" } },
    "allow": { ".read": "auth != null", ".write": false }
  }
}
```

그리고 **데이터 탭**에서 손으로 이렇게 넣어두면 그 4명만 통과합니다:

```
allow
 ├─ UID_kian   : true
 ├─ UID_joon   : true
 ├─ UID_eugene : true
 └─ UID_sean   : true
```

# B. GitHub Pages 배포 (관리자 1명, 약 5분)

**기존에 쓰시는 페이지와 충돌하지 않습니다.** GitHub Pages는 *레포지토리 1개당 사이트 1개*라,
새 레포를 만들면 주소가 하나 더 생길 뿐입니다.

1. GitHub → **New repository** → 이름 `minitf-studio` → **Public** → Create
   *(Private 레포의 Pages는 유료 플랜에서만 됩니다)*
2. **Add file → Upload files** 로 아래 4개를 올리고 Commit
   `index.html` `styles.css` `app.js` `database.rules.json`
3. **Settings → Pages** → Source `Deploy from a branch` → Branch `main` / `(root)` → **Save**
4. 1~2분 뒤 `https://<계정>.github.io/minitf-studio/` 접속

## B-1. 앱에 Firebase config 붙여넣기

배포된 주소로 들어가면 아직 Firebase를 모르니 **로컬 모드**로 뜹니다.

1. 닉네임 아무거나 넣고 들어가기
2. **설정 탭 → 실시간 공유(Firebase)** 칸에 A-4에서 복사한 config를 붙여넣기
   *(`const firebaseConfig =` 를 같이 붙여넣어도 앱이 알아서 걸러냅니다)*
3. **연결** → 자동 새로고침 → **로그인 화면**이 뜨면 성공

> 이 config는 **각자 브라우저에 한 번씩** 넣어야 합니다.
> 매번 넣기 번거로우면 `app.js` 맨 아래 `boot()` 위에 아래 한 줄을 추가해서 레포에 커밋해도 됩니다.
> (config는 비밀이 아니고, 실제 통제는 A-5 규칙이 합니다.)
>
> ```js
> if (!LS.get('fbconfig', null)) LS.set('fbconfig', { /* 여기에 config 붙여넣기 */ });
> ```

- 바꾼 비밀번호는 저도 모릅니다. 잊으면 저한테 얘기하시면 초기화해 드릴게요.
- AI 기능을 쓰려면 각자 무료 키가 하나 필요합니다 (아래 C 참고, 3분).

# C. Gemini API 키 (4명 각자, 3분)

**API 키 발급이 처음이면 이 순서 그대로 따라 하세요.**

1. <https://aistudio.google.com/apikey> 접속 → 구글 계정으로 로그인
   *(회사 계정이 막혀 있으면 개인 지메일로 하셔도 됩니다)*
2. 약관 동의 화면이 나오면 동의
3. **Create API key**(API 키 만들기) 클릭
4. 프로젝트를 고르라고 하면 아무거나 선택하거나 **Create API key in new project**
5. `AIzaSy...` 로 시작하는 **39자쯤 되는 문자열**이 나옵니다 → **복사** 버튼 클릭
   > 이 창을 닫아도 같은 페이지에서 다시 볼 수 있습니다.
6. 앱 → **AI 스튜디오 탭 → Gemini 연결** 칸에 붙여넣기 → **저장**
7. **연결 테스트** 클릭 → `✅ 연결 정상` 이 뜨면 끝. 이제 ①~④ 버튼이 활성화됩니다.

**모델 칸**은 비워두면 `gemini-2.5-flash` 를 씁니다(무료 티어에서 가장 빠름).
더 깊게 생각하게 하려면 `gemini-2.5-pro` 로 바꿔보세요 — 대신 무료 한도가 더 빡빡합니다.

### 키 취급 — 꼭 지켜주세요

* 키는 **각자 브라우저의 localStorage에만** 저장됩니다. Firebase에도, GitHub에도 올라가지 않습니다.
* 그래서 **4명이 각자 자기 키**를 넣습니다. 무료 할당량도 각자 씁니다.
* **절대 `app.js`에 키를 써넣고 GitHub에 올리지 마세요.** 공개 레포면 즉시 노출되고, 구글이 자동 감지해서 키를 정지시킵니다.
* 공용 PC에서 썼다면 나오기 전에 **“키 삭제”** 를 누르세요.
* 무료 키는 결제 정보 없이 쓸 수 있고, 한도를 넘으면 요금이 청구되는 게 아니라 그냥 막힙니다(429).

# 로그인 동작 정리

| 상황 | 동작 |
|---|---|
| 첫 로그인 | 초기 비밀번호로 들어오면 **바로 변경 화면**. 건너뛸 수 없습니다. 8자 이상, 초기 비밀번호와 달라야 통과 |
| 그 다음부터 | 바꾼 비밀번호로 바로 입장 |
| 나중에 또 바꾸고 싶을 때 | 설정 탭 → 내 계정 → **비밀번호 변경** (현재 비밀번호를 물어봅니다) |
| 비밀번호를 잊었을 때 | 관리자가 Firebase 콘솔 → Authentication → Users → 해당 계정 `⋮` → **비밀번호 재설정** → 새 임시 비밀번호 전달. `users/<uid>/pwChanged` 를 지우면 다음 로그인 때 다시 변경을 강제합니다 |
| 로그아웃 | 헤더 오른쪽 ⏻ 버튼 |

앱에서는 아이디(`kian`)가 그대로 닉네임이 되고, 헤더의 닉네임 칩을 눌러 바꿀 수 있습니다.
**참가자 명단은 여전히 익명 닉네임만** 씁니다 — 로그인 계정은 TF 4명 것뿐입니다.

# TF 4명 운영 흐름 (제안)

| 시점 | 하는 일 |
|---|---|
| 첫 모임 | 시작 템플릿 불러오기 → 조 이름·정원을 우리 상황에 맞게 수정 → 각자 아이디어 마구 투척 |
| 아이디어 정리 | 👍/🤔 투표로 자연스럽게 순위 → 상위 안을 **AI ① 확장**으로 3안씩 벌려보고 고르기 |
| 회의 끝날 때 | 메모를 **AI ③ 회의 정리**에 붙여넣기 → 할 일이 체크리스트로, 아이디어가 카드로 자동 등록 |
| 설계 | 타임테이블 블록 배치 → 대시보드에서 종료 시각 확인 → 예산 상한 대비 미터 확인 |
| 참석 조사 후 | 참가자 닉네임 등록 → **자동 배정** 또는 **AI ④ 추천** → 조별 인원·본사/파견 균형 확인 |
| 당일 | **AI ②** 로 타운홀 진행 멘트와 아이스브레이킹 퀴즈 뽑아서 그대로 사용 |

**자동 배정 규칙** — ① 희망 조를 먼저 채우고 ② 남은 인원은 본사/파견을 번갈아 꺼내
각 조의 소속 비율이 전체 비율에 가까워지는 쪽으로 넣습니다. 정원은 넘기지 않습니다.
(40명 · 5조 기준 테스트에서 각 조의 파견 비율 편차는 최대 6%p였습니다.)

# 산출물 뽑기 (사내로 옮길 때)

**대시보드 맨 위** 또는 **설정 탭 → 산출물 내보내기** 에 버튼 3개가 있습니다.

| 버튼 | 결과물 | 쓰는 곳 |
|---|---|---|
| 📄 **Markdown (.md)** | `워크숍기획서-{행사명}-{날짜}.md` | 사내 위키·노션·컨플루언스에 붙여넣기, 워드로 변환 |
| 🌐 **HTML (인쇄용)** | 같은 이름의 `.html` | 더블클릭하면 바로 열리고 **Ctrl+P → PDF로 저장**. 메일 첨부에도 그대로 |
| 📋 **MD 복사** | 클립보드 | 메신저·메일에 즉시 붙여넣기 |

두 파일 모두 이걸 담습니다:

1. **개요** — 일시·소요시간, 본사/파견 인원, 예상 참석, 조 정원, 총예산과 1인당 단가
2. **타임테이블** — 블록별 시작–종료 시각이 계산된 표
3. **조 편성** — 조별 요약표(인원/본사/파견/단가/활동비) + 조별 명단 + 미배정자
4. **예산** — 항목별 산식(`18,000원 × 11명`)과 합계, 상한 대비 비율
5. **준비물 · 할 일** — 담당·기한 포함 체크박스 목록
6. **아이디어** — 투표순 정렬, 설명과 코멘트까지

HTML은 **외부 리소스를 하나도 참조하지 않습니다.** 파일 하나만 옮기면 인터넷이 안 되는 사내 PC에서도 그대로 열리고 인쇄됩니다. `@media print` 를 넣어뒀으니 A4로 뽑으면 표가 중간에서 잘리지 않습니다.

> 이건 **읽는 문서**입니다. 앱으로 다시 불러오는 백업은 설정 탭의 **JSON 내보내기** 쪽입니다. 둘은 용도가 다릅니다.

# 모바일 사용

주 입력 환경이 휴대폰이라 이렇게 맞춰뒀습니다.

* 헤더는 스크롤과 함께 올라가고 **탭 바만 상단에 고정**됩니다 (헤더가 2줄로 접혀도 어긋나지 않게)
* 입력칸 글자를 16px로 둬서 **iOS 사파리가 입력할 때 화면을 확대하지 않습니다**
* 투표·삭제 같은 작은 버튼은 손가락용으로 터치 영역을 넓혔습니다 (`pointer: coarse`)
* 표는 페이지가 아니라 **표만 가로로 스크롤**됩니다
* 홈 화면에 추가해두면 앱처럼 씁니다 — 사파리 공유 → “홈 화면에 추가”

**다운로드 버튼은 PC에서 쓰세요.** 모바일 브라우저에서도 되지만 파일이 어디로 갔는지 찾기 번거롭습니다.
띄워놓고 보다가 필요할 때 PC에서 눌러 받는 흐름을 전제로 만들었습니다.

# 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 로그인 눌러도 “아이디 또는 비밀번호가 맞지 않습니다” | A-3에서 이메일을 `kian@minitf.local` 형태로 정확히 만들었는지 확인. 앱에는 `kian` 만 입력 |
| “Firebase 콘솔 → Authentication 에서 이메일/비밀번호를 사용 설정해야 합니다” | A-3의 2번을 안 한 겁니다 |
| “DB 접근 권한이 없습니다” | A-5 보안 규칙을 안 넣었거나 **게시**를 안 누른 겁니다 |
| 헤더 칩이 계속 `로컬` | config에 `databaseURL` 이 없습니다. A-2를 하고 A-4를 다시 복사하세요 |
| 4명이 서로 다른 내용을 봄 | **방 코드**가 다릅니다. 설정 탭 → 내 계정 → 방 코드를 모두 `minitf` 로 맞추세요 |
| AI 버튼이 회색 | C에서 키를 저장하지 않았습니다 |
| AI가 429 오류 | 무료 분당 한도 초과. 1분 뒤 다시 누르면 됩니다 |
| AI가 “네트워크 오류” | 사내망에서 `generativelanguage.googleapis.com` 이 차단된 겁니다. 개인 네트워크에서 시도해보세요 |
| 아무것도 안 뜨고 흰 화면 | 사내망에서 `gstatic.com`(Firebase SDK)이 막힌 경우. F12 콘솔을 열어 확인하세요 |

# 파일

```
index.html          화면 구조 (게이트 + 탭 7개)
styles.css          디자인 토큰 · 라이트/다크 테마 · 모바일 보정
app.js              스토어(Firebase/로컬) · 렌더 · 계산 · Gemini 호출 · 인증 · 산출물 생성
database.rules.json Firebase 보안 규칙
```

`app.js` 에서 바로 손댈 만한 것들:

* `TAGS` — 아이디어 태그 목록
* `AG_TYPES` — 타임테이블 블록 종류
* `DEF_SETTINGS` — 인원·참석률·시작 시각 기본값
* `SYS` — **AI에게 주는 워크숍 배경 설명.** 조직 상황이 달라지면 여기만 고치면 AI 답변 톤이 전부 바뀝니다
* `seed()` — 시작 템플릿의 조·타임테이블·아이디어·예산 내용
* `ID_DOMAIN` — 계정 뒤에 붙는 가짜 도메인 (`minitf.local`)
* `DEFAULT_ROOM` — 기본 방 코드 (`minitf`)
* `reportMarkdown()` / `reportHtml()` — 산출물 문서의 목차와 문구. 사내 양식에 맞춰 고치기 좋은 지점입니다
  (둘 다 `reportModel()` 이 정리한 같은 데이터를 받아 쓰므로, 항목을 추가하려면 `reportModel()` 부터 보세요)

색은 색약 검증을 통과한 8슬롯 팔레트를 고정 순서로 쓰고, 9번째 조부터는
새 색을 만들지 않고 회색으로 접습니다. 조를 8개 넘게 만들 일은 없을 겁니다.

# 알아둘 제약

* **사내망 차단** — `gstatic.com`(Firebase)이나 `generativelanguage.googleapis.com`(Gemini)이 막혀 있으면
  해당 기능만 꺼집니다. 배포 전에 회사 PC에서 한 번 열어보고 확인하세요.
* **동시 편집 충돌** — 같은 항목을 둘이 동시에 고치면 나중 저장이 이깁니다. 항목 단위로 쪼개 저장하므로 실무상 문제는 거의 없습니다.
* **백업** — 설정 탭의 **JSON 내보내기**로 언제든 파일로 뽑을 수 있습니다. 중요한 시점마다 한 번씩 눌러두세요.
* **개인정보** — 참가자는 익명 닉네임만 쓰도록 설계했습니다. 실명·사번·연락처는 넣지 마세요.
* **행사 후 정리** — 설정 탭 “보드 전체 삭제” 로 비우거나, Firebase 프로젝트를 통째로 삭제하세요.
* **브라우저** — 최신 Chrome/Edge 기준입니다.
